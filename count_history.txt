=============================================================================
                          COUNT_HISTORY INFORMATION
=============================================================================

1. OVERVIEW & PURPOSE:
----------------------
The 'Count_History' collection in Firestore is used by the mobile app's 
Analytics Service to display historical visitor statistics on the Weekly 
and Monthly charts.

2. WHY IT WAS NOT VISIBLE IN FIREBASE:
--------------------------------------
- Firestore does not display empty collections in the Firebase Console. 
- A collection only appears when it contains at least one document.
- Since 'Count_History' is populated only on a new day (date transition), 
  it remained hidden because the scripts were only run temporarily for 
  testing and stopped before midnight/date changes.

3. ARCHIVING LOGIC (How it gets created):
-----------------------------------------
The archiving logic is implemented in the Python counting backend:
File: d:\FYP\count(inference)\main.py

- Line 93-98: Checks if the current date is different from the saved 
  'last_reset_date' from Firestore.
- Line 113-132 (_archive_and_reset): Writes yesterday's total counts to 
  'Count_History' under a document ID matching the date (e.g., '2026-05-19'), 
  then resets the live daily counter 'VirtualLineCount/counter_1' to 0.

This means the collection will automatically be created when:
a) The python script runs continuously across midnight (date change).
b) Or when the python script is started on a new day and detects that 
   the last reset date in Firestore was yesterday.

4. FIRESTORE RULES ADJUSTMENT & REASON:
---------------------------------------
Even if 'Count_History' is empty, the mobile app queries it. If Firestore 
Rules do not define a read rule for 'Count_History', the query throws a 
'Permission Denied' exception. This exception blocks the entire analytics 
future, preventing today's live alerts from showing on the weekly/monthly charts.

Adding the following rule allows the app to query it without errors, returning 
an empty list when no history exists, and showing today's live data correctly:

match /Count_History/{docId} {
  allow read: if true;
}
